# Full Project Code Review — Fix Plan

**Report:** `docs/reviews/2026-10-03-code-review.md`

**Status:** Draft (awaiting approval)
**Date:** 2026-10-03

## Global constraints

- Fix findings **by their report IDs** (`CR-NNN`, `NV-1`). The report is the
  source of truth for evidence; this plan owns the sequencing and acceptance.
- House TDD: each fix writes/updates the failing test first, watches it fail,
  implements, then runs it. One commit per task, message style
  `fix(<area>): <what>` / `refactor` / `test` / `docs` as appropriate.
- After each task run `npm run typecheck`, `npm run lint`, `npm test` with Node
  22 (`export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"`).
- **`src/calculations/**` is protected.** Never edit it without explicit owner
  permission; tasks marked **[OWNER APPROVAL]** must not start until the owner
  approves.
- User-facing text changes must update **both** `src/i18n/en.ts` and
  `src/i18n/fa.ts` (key parity is enforced by `dictionaries.test.ts`).
- Generated files (`public/icons/`, `src/theme/accents.css`, `src-tauri/icons/`,
  generated parts of `src-tauri/gen/android/`) are regenerated by scripts, never
  hand-edited; regenerate with `npm run icons` / `accents` / `icons:native`.
- Follow AGENTS.md conventions: semantic MD3 utilities, logical direction
  utilities, base CSS only in `@layer base`, no code comments.
- Docs/prose fixes must keep `masterplan.md`, `AGENTS.md`, `README.md` and the
  in-app docs mutually consistent.

## Sequencing rationale

Order: (1) unblock the release pipeline and data-correctness Highs first;
(2) then correctness Highs and Mediums; (3) then shared-primitive accessibility
(one fix clears several IDs); (4) then quality/CI/docs; (5) resolve the security
lead; (6) deploy the calculator fixes only after owner approval.

## Dependencies / ordering

- Task 1 unblocks every later verification that runs `format:check`.
- Task 2 (import atomicity) resolves NV-1 and touches the same files as Task 4;
  do Task 2 first.
- Tasks 7 and 12 both touch shared UI/theme files; keep them sequential.
- Task 15 is gated on owner approval; it can otherwise run anytime.
- All other tasks are independent and may run in parallel once Task 1 lands.

## Risks + rollback

- **Behavior changes:** Tasks 3, 4, 5, 6 and 7 change validation and UI behavior;
  each is covered by a failing-first test and a single commit, so it can be
  reverted independently.
- **Generated artifacts:** Task 12 regenerates `accents.css` and Task 13
  regenerates Android icons; verify the diff is only the intended change and
  never hand-edit the outputs.
- **CI changes:** verify workflows parse before pushing a tag; a broken workflow
  blocks releases.
- **Rollback:** `git revert <commit>` per task; no migrations or data formats are
  irreversibly changed (Task 2/3 only add robustness).
